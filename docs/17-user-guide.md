# 中转站桌宠 · 使用手册

> 给使用者看的。你不需要懂代码。
> 本文所有按钮名称、提示文字都对照真实实现核对过；**没实现的功能不会写进来**。
> **如果你是把桌宠作为 DSH 插件在用，入口完全不同——看 `09-onboarding.md`，本篇讲的是「独立模式」（双击桌面快捷方式）。**

---

## 30 秒版

1. **双击桌面「桌宠」** —— 桌面上会出现一条桌宠，后台服务跟着起来。
2. **双击桌面「中转站管理」** —— 浏览器自动打开管理页。
3. **粘 URL → 点「识别」→ 填凭证 → 点「添加」** —— 搞定，回到列表点「刷新」就能看到余额。

> ⚠️ **顺序不能反**：先开「桌宠」，再开「中转站管理」。管理页要靠那个服务才能打开。

## 一、第一次使用

### 第 1 步 · 双击桌面「桌宠」

| | |
|---|---|
| **在哪** | 桌面上，名字就叫「桌宠」 |
| **会发生什么** | 桌宠出现；后台起一个服务，这个服务的地址是 `http://127.0.0.1:3080` |
| **重复双击会怎样** | **没关系**。已经在跑就什么都不做，不会出现两只桌宠 |
| **怎么知道成功了** | 桌宠出现在屏幕上。想再确认，可以打开 <http://127.0.0.1:3080/health>，能看到一段文字就说明服务活着 |
| **失败怎么办** | 打开 `%USERPROFILE%\.dsh\dsh-pet\launcher.log` 看最后几行。最常见原因是**端口 3080 被占用**——已经有一只桌宠在跑，或者 **DSH 正占着这个端口**（那就说明你是 DSH 用户，看 `09-onboarding.md`） |

### 第 2 步 · 双击桌面「中转站管理」

| | |
|---|---|
| **在哪** | 桌面，名字叫「中转站管理」 |
| **会发生什么** | 系统默认浏览器自动打开 `http://127.0.0.1:3080/admin` |
| **打不开/一片空白？** | 99% 是服务没起。**回去做第 1 步**，再点一次「中转站管理」 |
| **点了之后一直没反应（干等约 30 秒）？** | 说明 3080 被别的东西占着——**多半是 DSH**。这时的正确做法不是反复点，而是走 DSH 的设置页（见 `09-onboarding.md`）。⚠️ 当前版本这一步**不会有任何提示**，是已知问题 |
| **页面长什么样** | 最上面是「**识别站点类型**」，往下是「**新增站点**」，再往下是「**站点列表**」，最下面还有「**消耗与预计可用天数**」和「**模型矩阵**」 |

### 第 3 步 · 先「识别站点类型」

页面第一块就是它。这里**只填网址，不填凭证**。

1. 在 URL 框里粘贴站点地址，例如 `https://api.example.com`
2. 点「**识别**」
3. 下面会显示识别结果：**类型 / 把握程度 / 依据**

**为什么必须先做这一步？**
类型认错了，后面查余额的接口就全错，你会看到「查不到」但不知道为什么。页面自己也提示了这句话：**先「识别站点类型」确认类型，再「新增站点」**。

**识别不了怎么办？**
它会直接告诉你缺什么证据，**不会瞎猜**。这时你可以：
- 直接在「新增站点」里手动选类型；
- 或者干脆选「手工」凭证类型，先手工记余额。

### 第 4 步 · 「新增站点」

| 字段 | 填什么 | 注意 |
|---|---|---|
| **名称** | 随便起，能认出来就行 | 必填 |
| **URL** | 站点根地址 | 带不带 `/v1` 都行，会自动处理。**但不要带 `/api` 这种路径** |
| **类型** | 第 3 步识别出来的 | 识别不了就手选 |
| **凭证类型** | 见下面第二节 | 这是最容易选错的地方 |
| **凭证值** | 对应的 Key 或令牌 | 提交后输入框会自动清空 |
| **附加头** | 一般不用填 | 老站点提示要「用户 ID」时才用 |

填完点「**添加**」。站点会出现在下面的「站点列表」里。

### 第 5 步 · 看余额

在「站点列表」里找到刚加的站，点这一行的「**刷新**」。

- 「健康」那一栏变成「**在线**」
- 余额位置出现数字

→ **成功。** 桌宠那边也会跟着更新。

## 二、加站点：凭证怎么选（最容易卡的一步）

### 先说结论

**大多数情况用 API Key 就够了，不需要专门去生成系统访问令牌。**

模型 API Key（`sk-` 开头那种）已经能拿到：**已用金额**、**是不是无限额度**、**模型清单**。真站实测过，能用。

两种顺序别搞混：

- **按「省事」排（推荐你这么做）**：`API Key → AccessToken → Cookie（高级） → 手工填写`
  （API Key 你手上就有；AccessToken 要额外生成；Cookie 会失效；手工什么都不用）
- **按「看到的钱最全」排**：`AccessToken → API Key → Cookie → 手工填写`

**区别就一句话**：AccessToken 能看到**你账户一共有多少钱**；API Key 只能看到**这一个 Key 名下用了多少**。你如果只想知道"这个 Key 用了多少 / 还能用多少"，API Key 足够。

### 在哪拿到

| 凭证类型 | 去哪拿 | 注意 |
|---|---|---|
| **API Key** | 站点后台 → **令牌管理 / API Keys** → 新建 → 复制 `sk-` 开头那串 | 别把**别的站**的 Key 粘过来，会认证失败 |
| **AccessToken**（系统访问令牌） | 站点后台 → **头像 → 个人设置 → 系统访问令牌 → 生成** | 老版本 one-api 的位置可能不一样，**以你的站点版本为准** |
| **Cookie** | 浏览器按 F12 → 「网络」→ 找一条 `api/user/self` 请求 → 复制里面的 Cookie | **高级选项**。你重新登录一次它就失效，不建议长期用 |
| **手工填写** | 什么都不用 | 直接填一个金额数字。见下面「兜底」 |

### 兜底：手工填写

有些站就是不给你查（站长关了接口、被 Cloudflare 挡着、或者凭证类型对不上）。

这时候**选「手工」凭证类型，直接填一个金额**。

- 界面会给这个站打上「**手工**」标签
- **手工的站不参与低余额告警**——因为它不是实时数据，拿一个过期数字告警只会吓你
- 手工填的数**不会被自动刷新覆盖**；哪天想改回自动，重新配个凭证就行

> 这不是"失败方案"。**有一部分中转站查不到余额是必然的**，能手工记下来已经比开十个网页强。

## 三、看懂了什么（界面上的字都是什么意思）

### 「无限额度 · 已用 $34.58」

**这不是余额，是「你已经花了多少」。**

有些站长会把 Key 设成「无限额度」。这种情况下压根没有"还剩多少"这回事，所以只能告诉你用了多少。

- 这类站**不参与低余额告警**（没有余额可以告警）
- 看到这个提示，别以为"我还有无限的钱"，它只说明这个 Key 没设上限

### 「⚠ 换算率未确认，请核对」

站点内部用一种计数单位记账（默认 **50 万 = 1 美元**），但**站长可以改这个比例**。

**它是怎么来的？** 新建站点时，换算率默认是「**未确认**」状态——因为程序还没从站点打听到真实比例。所以：

> 📌 **你刚加完站点就看到这行提示，是正常的，不是你填错了。**
> 它只表示「这个站的换算率还没被确认过」。

**为什么必须确认？**
比例填错 **1000 倍**，余额就会显示成实际值的千分之一 → **低余额告警永远不会触发**，等你发现时已经欠费了。

（未确认的站点**不参与低余额告警**——这是故意的，避免拿一个可能差 1000 倍的汇率去报警。）

**怎么确认（30 秒，别手工算）：**
1. **先点「识别」**——如果它打听到了真实比例，会直接给一个建议值，**采用即可**，下面两步可以跳过
2. 只有当识别**没给**建议值时，才需要手工核对：
   - 打开站点后台，看它显示的余额，比如 `$10.00`
   - 看管理页显示的数字
   - **对不上就手动改换算率**，改到一致为止

### 「数据不足」（在「消耗与预计可用天数」里）

要算出"还能用几天"，需要**连续观测 3 天以上**才有消耗速率。

观测不够就显示「**数据不足**」，**绝不会给你 0 或 ∞**。

- 「∞」看着爽，但是假的
- 「0 天」会让你以为马上要停机，也是假的
- 宁可说"不知道"，也不编一个数给你

### 「手工」标签

这个站的余额是你手填的，不是查出来的。
→ **不参与告警**，也不会被自动刷新覆盖。

### 「健康」那一栏

| 显示 | 意思 | 你该做什么 |
|---|---|---|
| **在线** | 能连上 | 没事 |
| **不可达** | 连不上 | 检查 URL 有没有填错（尤其别带 `/api` 这种路径）、网络/代理 |
| **被拦截** | 被站点的 Cloudflare 人机验证挡住了 | 先手工填余额，见常见问题 |
| **未探测** | 还没查过 | 点一下「健康」 |

### 「模型矩阵」

这一块告诉你**哪个站有哪个模型**。三种状态要分清：

| 显示 | 意思 |
|---|---|
| 有 / 该站有这个模型 | 确认有 |
| 抓过，确认没有 | 查过了，确实没有 |
| **没抓过 = 未知（不是没有）** | 没查过，**不代表没有** |

「未知」和「没有」是两件不同的事。没查过的站，我们不会说它没有。

另外页面会说明「几个站未抓取（未知 ≠ 没有）」，以及哪些站**算不出**预计天数。

### 底部的「合计」

所有站余额加在一起。注意两点：
- **无限额度的站不计入合计**（它没有"余额"这个东西）
- 不同币种不会硬加在一起

## 四、桌宠会怎么提醒你

| 情况 | 桌宠的表现 |
|---|---|
| 一切正常 | 正常待机 |
| 有站余额偏低 | 桌宠**变脸** + 冒**气泡**告诉你哪个站快没钱了 |
| 无限额度的站 | **不告警**（只显示已用） |
| 手工填的站 | **不告警**（不是实时数据） |
| 想立刻看全部 | 右键桌宠或用管理页的「刷新全部」 |

点气泡能看是哪个站出的问题。

## 五、常见问题

**1. 管理页打不开 / 一片空白**
→ 服务没起来。**先双击桌面「桌宠」**，等 2 秒，再点「中转站管理」。
→ 如果「桌宠」也起不来：**目前它不会弹窗告诉你**，但有两处能看——
　① 日志文件 `%USERPROFILE%\.dsh\dsh-pet\launcher.log`（每次启动都往这里追加一行，失败原因写在最后一行）；
　② 启动脚本会以**非零退出码**结束（从命令行跑时能直接看到）。
→ 最常见原因是**端口 3080 被占用**（已经有一只桌宠在跑了，或 DSH 占着这个端口）。
→ 如果你本来就是在用 DSH 插件，**这篇的快捷方式不适用**，见 `09-onboarding.md`。

**2. 加了站点，但余额显示「查不到」**
按这个顺序查：
1. **健康那一栏是什么？** 「被拦截」→ 见第 5 条；「不可达」→ URL 或网络问题
2. **凭证类型选对了吗？** 填的是 `sk-` 开头的却选成了「AccessToken」，会认证失败
3. **这个 Key 是不是无限额度？** 是的话界面会显示「无限额度 · 已用 $X」，这是正常的
4. 都不对 → **改用手工填写**，先用起来

**3. 为什么 API Key 查不到「账户总余额」？**
这是站点的设计，不是我们的 bug：**账户级接口只认系统访问令牌（AccessToken）**。
用 API Key 时，我们走的是另一个接口，能拿到「这个 Key 用了多少 / 是不是无限额度」。
→ 想看账户总额，就在站点后台生成一个 **AccessToken** 填进去。

**4. 提示端口被占用 / 服务起不来**
→ 说明**已经有一只桌宠在跑了**。这是故意的：只允许跑一只，避免两只桌宠抢同一份数据。
→ 想重开：先双击「**关闭桌宠**」，等它提示"已关闭"，再双击「桌宠」。

**5. 健康显示「被拦截」**
→ 站点的 Cloudflare 人机验证把程序挡住了。
→ **现在先用手工填写余额**；自动绕过需要浏览器桥，属于后续版本的能力。
→ 顺带一提：浏览器里能正常打开 ≠ 程序能访问，人机验证只针对"疑似自动化"的请求。

**6. 我的凭证存在哪？安全吗？**
**如实说：目前是明文存在你的本机磁盘上。**

- 位置：`%USERPROFILE%\.dsh\dsh-pet\relays\relay-credentials.json`
- **不会上传到任何服务器**，只在你和你的站点之间用
- 界面上永远只显示掩码（如 `sk-v****7890`），**页面里不会出现完整 Key**
- **但它是明文**。所以：别把这个文件发给别人、别传到网盘/代码仓库
- 系统级加密（Windows 凭据管理器）在后续版本计划里，**当前版本没有**

**7. 余额数字和站点后台对不上**
→ 十有八九是**换算率**问题。见第三节「换算率未确认」的核对方法。
→ 如果是差 1000 倍这种量级，就是换算率填错了，改一下即可。

**8. 站点加了，桌宠却没反应**
→ 确认这个站是**启用**状态（列表里能刷新出余额）；
→ 再点一次「刷新」或「刷新全部」；
→ 手工填的站不会触发告警，所以桌宠本来就不会为它变脸。

## 六、不用了怎么关

**双击桌面「关闭桌宠」。**

它会通知服务正常收尾（先把桌宠窗口退掉，再停服务），最多等 15 秒，然后打印「已关闭」。

⚠️ **不要用任务管理器直接杀进程**——强杀会让桌宠窗口留下半透明残影，也容易误杀别的同名进程。

关掉之后：管理页就打不开了（服务停了），这是正常的。下次双击「桌宠」即可恢复，站点和凭证都还在。

## 附：文件都在哪

| 内容 | 路径 |
|---|---|
| 数据根目录 | `%USERPROFILE%\.dsh\dsh-pet\` |
| 站点列表 | `…\relays\relays.json` |
| **凭证（明文）** | `…\relays\relay-credentials.json` |
| 启动/停机日志 | `…\launcher.log` |

> `%USERPROFILE%` 就是你 Windows 的用户目录，例如 `C:\Users\你的名字`。
> 如果你设了 `DSH_HOME` 环境变量，上面所有路径改成 `%DSH_HOME%\dsh-pet\`。
