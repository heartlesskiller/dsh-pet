## 2. 项目定位与不可动的红线

**双目标**（`docs/PLAN-v1.md`）：
1. 桌宠适用于**所有 agent**（不只 DSH）—— 落点是 `gateway`（能力自述 / 在场登记 / 事件摄入 / SSE）与独立模式；
2. 管理**多个 LLM API 中转站**（余额 / 健康 / 站点切换 / 模型覆盖）—— 落点是 `relays`。

**红线（改动前先读这条，否则会推翻上游设计）**：

| # | 红线 | 出处 |
|---|---|---|
| R-a | `sections.relays` 与 `sections.balance` **并存不合流**。上游的单服务商余额链路一行都不能改 | PLAN 修订 #2 |
| R-b | 金额换算唯一权威在 `host/relays/money.ts`；**探测不到换算率必须标 `rateUnconfirmed`，绝不静默默认**（无标记兜底入口已拆） | 修订 #11 / #19 |
| R-c | 脱敏唯一出口 `relays/redact.ts`；每个 `/relays` 响应返回前过 `assertNoSecret`，检出明文就 500 —— **宁可端点坏掉，不泄密** | PLAN §7 |
| R-d | 凭证类型之间**不自动降级**（API Key 失败了不会拿 AccessToken 重试）；被 CF 拦 / 429 也不换端点重试 | 修订 #20 / #23 |
| R-e | **绝不伪造 0 余额**：查不到就是查不到，落 `fetch-error` / `credential-missing` / `blocked` / `rate-limited` | PLAN §5 |
| R-f | `/relays` 子域的**动作端点直接返回数据**是「子域例外」，**不得扩散**到 `/balance` `/whisper` 等既有端点（它们仍是「动作只回 ok，数据走 /state」） | API.md §0.3 |

### 3.2 newapi 取数链路（最容易被改坏的地方）

```
凭证 kind = api-key        → ① /api/usage/token/          （第一优先，令牌级）
                            ② billing 双端点（/dashboard/billing/subscription + /v1/dashboard/billing/usage）
凭证 kind = access-token   → ① /api/user/self             （账户级）
/ session-cookie           ② /api/usage/token/  → ③ billing
```

**四守卫**（每一条都对应真站证据，见 `docs/10-real-site-verification.md` F1–F9）：
1. `unlimited_quota` 布尔或 `1e8` 哨兵 → 该站是无限额度：`data.total` 放**已用金额**，客户端渲染「无限额度 · 已用 $X」，**绝不渲染成余额**，也**不计入舰队剩余合计**；
2. `total_available` 为负 → 抛错，绝不当余额；
3. 分 vs quota **单位隔离**（`total_used/100` 与 quota 除法不能混）；
4. HTTP 200 + `success:false` / `code:false` → **判失败**（真站 API Key 打 `/api/user/self` 就是这个形态）。

## 5. 当前缺口（接手第一优先级）

### 5.1 ⚠ 独立模式没有管理页 —— 用户试用时「看不到中转站面板」

**事实**：`relays-admin.ts` 是一个 **DSH 设置页的 slot**（`ctx.slots.register({ name: 'settings.section', id: 'relays-admin', order: 31 })`）。
独立模式的伪 ctx 里 slot 注册是 **no-op**（`src/standalone/context.ts`），并且服务只注册了 API 前缀路由，
**没有任何 HTML 页**。所以双击桌面快捷方式的用户：能看到桌宠气泡汇总（T04），但**没有任何 UI 可以添加站点**。

**这是产品级的死循环**：没站点 → 气泡没数据 → 也没地方加站点。

**建议实现**（最小可用，约 0.5–1 天）：
1. 在 `src/standalone/server.ts` 或 host 前缀路由里加 `GET /admin`（HTML，返回一张单页）；
2. 页里内联一个极简脚本，直接 `fetch('/dsh-pet-7340/relays')` 做 CRUD（body 形状就是 `RelaySiteInput` + `credential`，见 `openapi.yaml`）；
3. **不要**试图把 2423 行的 React 组件直接搬到独立模式（它依赖 DSH 的 React/h 注入与 slot 生命周期）—— 独立页用原生 DOM 或预构建 bundle 都行，但**别改 relays-admin.ts**；
4. 判定标准：`curl -s localhost:3080/admin | grep 中转站` 有内容；页面上能新增/刷新/看余额；
5. 顺手把入口做成：桌宠气泡上「点一下打开 `/admin`」或在 `stop-pet` 旁边加一个「中转站管理」快捷方式。

**临时替代**（现在就能用，可写进用户手册）：
```bash
curl -s -X POST http://127.0.0.1:3080/dsh-pet-7340/relays \
  -H 'content-type: application/json' \
  -d '{"name":"我的站","url":"https://your-site.com","kind":"new-api",
       "credential":{"kind":"api-key","secret":"sk-xxxx"}}'
curl -s http://127.0.0.1:3080/dsh-pet-7340/relays          # 列表（凭证已脱敏）
curl -s -X POST http://127.0.0.1:3080/dsh-pet-7340/relays/refresh-all
```

## 7. 环境事实（不知道这些会误判「代码坏了」）

| 现象 | 真实原因 | 正确做法 |
|---|---|---|
| 沙箱里 Electron 反复崩、日志刷 `GPU process isn't usable` | 沙箱不允许 GPU 子进程 | 不要试图改代码「修」它；真机验证交给用户桌面 |
| 从工具里起的服务/桌宠，命令一结束就全没了 | 工具侧进程树带 `KILL_ON_JOB_CLOSE`，父进程退出即被内核收走 | 需要持久运行的服务只能由用户双击快捷方式/在终端里起 |
| `WScript.Shell`（COM）与 PowerShell `Add-Type` 被拒 | 安全策略硬禁 COM 实例化与运行时编译 | 建 `.lnk` 用 `tools/make-shortcut.mjs`（Electron 原生 `shell.writeShortcutLink`） |
| Electron 报 `Cannot find module 'electron'` | 环境里带着 `ELECTRON_RUN_AS_NODE` | 启动前 `delete env.ELECTRON_RUN_AS_NODE`（**不能设空串**，会 abort） |
| `import x from './relays'` 报错 | Node ESM 不做目录索引（**只在跑测试时炸**，bundler 会兜住） | 一律写 `'./relays/index'`（纪律 E2） |
| 端口 3080 起不来 | S0 单实例锁：**不再顺延**，明确失败 | 先 `curl /health` 看是不是自己人；要停就 `POST /shutdown` |
