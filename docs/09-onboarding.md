# DSH 插件形态 · 上手引导

> **如果你只用「独立模式」（双击桌面「桌宠」那种），看 `17-user-guide.md` 就够了，这篇可以跳过。**
> 这篇只讲一件事：**当桌宠是作为 DSH 插件跑的，你要点哪里。**
> 本文所有入口、按钮、路径均已读代码确认（`src/client/app.ts`、`src/client/relays-admin.ts`、`src/host/index.ts`），不凭印象。

---

## 一、先分清你在用哪种形态

同一个程序有两种跑法，**入口完全不同**，混了就会「找不到按钮」。

| | **DSH 插件形态**（本篇） | **独立模式**（`17-user-guide.md`） |
|---|---|---|
| **谁在跑** | DSH 自己加载插件，**你什么都不用启动** | 你双击桌面「桌宠」拉起一个独立服务 |
| **管理入口** | DSH **设置页**里的一节「中转站管理」 | 浏览器打开 `http://127.0.0.1:3080/admin` |
| **桌宠长在哪** | 看这只宠物的 `display` 设置：`web`/`both` 在 **DSH 界面里**，`desktop`/`both` 在**桌面透明小窗**（代码**不设默认值**，必须显式写） | 一直是桌面透明小窗 |
| **要不要管服务** | ❌ **不用**，也没有「关闭桌宠」这回事（关 DSH 就行；详见第三节） | ✅ 要，先起服务才有管理页 |
| **数据存哪** | `<DSH_HOME>/dsh-pet\relays\` | **同一个地方**（见第四节，这点最容易误会） |

> `<DSH_HOME>` 默认是 `C:\Users\你的名字\.dsh`。

## 二、从零到看到第一个站点余额（3 步）

### 前提：插件已装好

在 DSH 终端里装（只装一次）：

```
dsh plugin --profile web add dsh-pet
```

- 用 DSH **桌面应用**的，profile 换成 `desktop`（以你 DSH 的版本为准）
- 装完**重启 DSH**，桌宠才会出现

### 第 1 步 · 打开 DSH 设置页，找「中转站管理」

- 位置：DSH **设置**页的**左侧导航**里
- 它在「**桌宠配置**」的**下面一项**（代码里两节紧挨着，order 30 / 31）
- 点进去，页面第一句是：「管理 LLM API 中转站：余额、连通性与焦点站点……」

**找不到这一节？**
→ 说明插件没加载成功。检查上一步的 `dsh plugin add` 有没有报错，然后**完整重启 DSH**（不是刷新页面）。

### 第 2 步 · 先「识别站点类型」，再「新增站点」

和独立模式**完全一样的流程**，只是换了个地方：

1. 页面最上面的「识别站点类型」—— 粘 URL，点「识别」
2. 看识别结果（类型 / 把握程度 / 依据）
3. 到「新增站点」填名称、URL、类型、凭证
4. 点「添加」

> 详细字段说明、凭证怎么选、去哪拿 Key，**全部在 `17-user-guide.md` 第二节**，这里不重复。

### 第 3 步 · 回到「站点列表」点「刷新」

「健康」显示「在线」、余额出现数字 → 成功。桌宠那边会跟着变。

界面上的「无限额度 · 已用 $X」「⚠换算率未确认」「数据不足」「手工」标签分别是什么意思，**见 `17-user-guide.md` 第三节**。

## 三、桌面那三个快捷方式，在 DSH 形态下怎么用

装上这个 fork 后，桌面会有三个 `.lnk`。**如果你是 DSH 插件用户，三个都不需要点——但原因各不相同，见下表。**

| 快捷方式 | 在 DSH 形态下 | 原因（读代码确认） |
|---|---|---|
| **桌宠** | ⚠️ **不需要点**（点了也会被拦住并告诉你原因） | 它要拉起「独立服务」，但 DSH 自己占着默认端口 `3080`。现在**约 1 秒内**就会提示「端口 3080 被 DSH 或其它程序占用 / DSH 用户不需要双击这个快捷方式」。桌宠已经在 DSH 里跑了 |
| **关闭桌宠** | ✅ **点了也没事，但没用** | 它先探 `/health`，必须自报名字 `dsh-pet-standalone` 才动手。DSH 的服务不是这个名字 → 它只会打印「没有在运行的桌宠」，**不会关掉 DSH** |
| **中转站管理** | ⛔ **不需要用**（现在会立刻指路） | 它同样是「先确保独立服务在跑，再开 `/admin`」。现在**约 1 秒内**就结束并告诉你原因，**不会再开一个 404 页面、也不会干等**。**DSH 用户请走设置页** |

> 一句话：**DSH 形态下，这三个快捷方式都可以当成不存在。** 你只需要 DSH 自己。

> ✅ **已修复（`105e8d4`）**：以前双击「中转站管理」会**干等 30 秒然后什么都不发生**；现在会在**约 1 秒内**告一段落，并明确告诉你：
> > 端口 3080 上跑的不是独立模式的桌宠（很可能是 DSH 宿主）。
> > 如果你是 DSH 用户，请到 DSH 设置页 → 中转站管理（在「桌宠配置」下面一项）。
> > 不需要双击这个快捷方式。
>
> 实测：**约 0.7 秒结束、不打开浏览器、不会去启动服务**。
> 但**仍然建议你直接用设置页**——那才是 DSH 形态的正确入口。
>
> 📌 **如果那个控制台窗口一闪而过**，原因同时写在 `<DSH_HOME>\dsh-pet\launcher.log` 里，去看最后几行即可。

## 四、数据只有一份（别配两遍）

这是最容易误会的地方：**两种形态读写的 `relays.json` 和 `relay-credentials.json` 是同一份文件。**

```
<DSH_HOME>\dsh-pet\relays\
    relays.json              ← 站点列表
    relay-credentials.json   ← 凭证（明文，见 17 第五节 Q6）
```

依据：`dshHomeDir()` 在两种形态下都是 `process.env.DSH_HOME || <用户目录>\.dsh`，站点目录都挂在它下面的 `dsh-pet\relays`。

**所以：**
- 在 DSH 设置页加过的站，独立模式打开 `/admin` 也能看到（反之亦然）—— **不用配两遍**
- ⚠️ **但别同时开两个**：独立模式和 DSH 插件同时往同一份 `relays.json` 写，可能互相覆盖
- ⚠️ **例外**：如果你给独立模式单独设了 `DSH_HOME` 环境变量，那就是两份独立数据了

## 五、DSH 形态专属问题

**1. 设置页里找不到「中转站管理」**
→ 插件没加载。先确认 `dsh plugin add` 没报错，再**完整重启 DSH**（不是刷新页面）。

**2. 双击了桌面「桌宠」，立刻报「端口被占用」**
→ 这是**正常现象**，不是故障——它在告诉你「DSH 用户不需要这个快捷方式」。以前要干等 30 秒，现在约 1 秒就结束。
→ 失败原因同时写在 `<DSH_HOME>\dsh-pet\launcher.log`（「桌宠」快捷方式会停住控制台让你看清，按任意键关闭）。
→ 如果你确实想用独立模式：先**完全退出 DSH**（它会释放 3080），再双击「桌宠」。
→ ⚠️ **不要用「设 `DSH_PET_PORT` 换端口」来绕过**：那样独立模式会和 DSH 并行跑，**两边写同一份站点配置，可能互相覆盖**。

**3. 桌宠不出现**
→ 检查这只宠物的 `display` 设置。四个取值：`web`（只在 DSH 界面里）/ `desktop`（只在桌面小窗）/ `both`（都显示）/ `none`（都不显示）。
→ 最省事：**右键桌宠 → 菜单里切「仅网页 / 仅桌面 / 两者」**。

**4. 想让桌宠浮在桌面上，而不是待在 DSH 界面角落**
→ 右键桌宠，选「**仅桌面**」或「**两者**」。
→ 选「仅桌面」后，DSH 界面里就看不到它了，它会以透明小窗出现在桌面上。

**5. 关了 DSH，桌宠还在？**
→ 独立模式的服务不会自己停。双击桌面「**关闭桌宠**」收尾。
→ 如果它提示「没有在运行的桌宠」，说明本来就没了，不用管。

**6. 加了站点但 DSH 里的桌宠没反应**
→ 与独立模式相同：确认站点是**启用**状态、点一次「刷新」；**手工填的站和无限额度的站不会触发告警**（见 17 第三、四节）。

---

## 一句话总结

**装插件 → 重启 DSH → 设置页 → 中转站管理 → 识别 URL → 填凭证 → 添加 → 刷新。**
桌面那三个快捷方式在 DSH 形态下都不用管；数据和你独立模式看到的是同一份。
